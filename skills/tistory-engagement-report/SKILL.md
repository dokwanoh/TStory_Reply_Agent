# 티스토리 확산 결과와 원장 요약

1. 사용자 지정 프로젝트와 실제 `.local/state/ledger.json`을 확인한다. [CLI 계약](../tistory-engagement/references/ledger-cli.md)을 참고한다.
2. 질문의 범위를 먼저 맞춘다. `방금`은 현재 run, `그 앞`은 바로 전 run, `오늘`은 KST 오늘이다. 실행 세션과 run은 구분한다.
3. `status --run-id UUID`로 해당 요청만 조회한다. 댓글·링크가 필요하면 `--details`를 쓴다. 여러 요청의 수를 합쳐 현재 요청의 완료로 표현하지 않는다.
4. `report UUID`로 비공개 Markdown·JSON 요약을 저장한다. 원본 원장·방문·예약·영수증·실패 이력은 삭제하거나 요약으로 치환하지 않는다.
5. 확산이 모두 끝나면 이 요약을 **항상** 남긴다. `run-finish`는 자동으로 요약한다. 중단·인계로 열린 run도 `report`한다.

## 집계

- 같은 글의 댓글·신규 구독·공감이 모두 confirmed인 경우만 **3종 완료 1바퀴**다. 서로 다른 미구독 블로그 조건을 지킨다.
- 행동별 실제 수는 별도로 보여준다. 댓글 3·구독 2·공감 2라고 3바퀴 완료로 부르지 않는다.
- 기존 구독·내 댓글·이미 켜진 공감은 신규 성공 수에 넣지 않는다.
- 예약·방문·초안·버튼 클릭은 성공 증거가 아니다. pending·uncertain·not_submitted를 confirmed에서 제외한다.
- 과거에 초기 관찰이나 loop 목표가 없으면 실제 행동 수는 보고하되 새 정의의 바퀴 수를 추측하지 않는다.
- 남은 바퀴, 부분 완료, 후보 제외와 이유, pending 예약 수, 활성 작업기 수, 3회 실패 인계 여부를 함께 확인한다.

## 사용자에게 보여줄 내용

기본 보고는 짧게 쓴다.

- 이번 요청: **목표 N / 3종 완료 M / 남음 R**
- 실제 확정: 댓글 C · 신규 구독 S · 공감 L
- 부분 완료·미확인·중단 사유와 다음 행동
- 글마다 실제 URL과 댓글 전문, 구독·공감 결과. 링크 요청이면 각 글 제목을 클릭할 수 있게 제공한다.
- 등록 미확인 문장은 **시도문**으로 구분한다. 실제 게시 댓글로 소개하지 않는다.
- 비공개 요약 파일 링크

완료 시 진행 상태와 실적을 구분한다. 중단됐으면 완료라고 쓰지 않는다. 기존 기록의 성공을 새 세션 성과로 옮기지 않는다. 0건도 정확히 보고한다. 조회만 요청했을 때 브라우저 반응을 실행하지 않는다.
