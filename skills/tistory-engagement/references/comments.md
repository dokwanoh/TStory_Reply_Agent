# 댓글 작성 기준

본문을 충분히 읽고 자연스럽게 든 인상 하나를 고른다. 글의 구체적인 내용은 소감이 맞는지 확인하는 근거로 사용하되 내용을 억지로 요약하는 문장으로 만들지 않는다.

- 친근하고 정겨운 존댓말을 쓴다. 자연스러운 `네요`, `좋아요`, `괜히`, `은근` 정도는 좋지만 유행어·웃음·감탄사를 억지로 넣지 않는다.
- 소감은 짧은 한 문장, 8–120자다. `좋은 글 잘 봤어요`처럼 어느 글에나 붙는 문구만 쓰지 않는다.
- 글쓴이의 말투와 글의 무게를 존중한다. 사고·질병·사별 등 무거운 글에는 장난스러운 표현을 쓰지 않는다.
- 실제로 경험하지 않은 방문·구매·사용을 했다고 쓰지 않는다. 추측을 사실처럼 쓰지 않는다.
- 본문과 무관한 홍보·링크·구독 답례 요구는 넣지 않는다.
- 미구독 추가 문장은 **자주 교류해요~**다. 실제 댓글에서는 Markdown 별표 없이 적는다. 이는 답례 요구로 확장하지 않는다.
- 사용자가 특정 본문을 그대로 지정하는 등 새 지시를 하면 그 지시를 우선하고 기존 규칙과 충돌 여부를 분명하게 처리한다.

예시는 해당 본문을 실제로 읽었을 때의 문체 참고이며 복사할 템플릿이 아니다.

- 프로그램 설정 과정을 다룬 글: `헷갈리던 설정이 이렇게 정리되니 한결 편하게 느껴지네요.`
- 산책의 작은 즐거움을 다룬 글: `소소한 풍경인데 읽는 저까지 괜히 마음이 포근해지네요.`
- 미구독일 때: 위 소감 뒤에 공백 한 칸과 `자주 교류해요~`를 붙인다.

CLI의 `comment` 명령은 문장 길이·한 문장·조건부 인사 형식만 검사한다. 본문 이해, 친근함, 사실성은 실행 에이전트가 판단해야 한다. CLI 통과를 댓글 품질 검토의 대체로 쓰지 않는다.
