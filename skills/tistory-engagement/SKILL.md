# 티스토리 확산 실행

## 시작

1. 사용자 지정 프로젝트의 `AGENTS.md`와 `RUNBOOK.md`를 읽고 `reply_agent/`가 있는 프로젝트 루트를 찾는다. 설치된 스킬 디렉터리를 실행 원장으로 쓰지 않는다.
2. 로컬 `.local/state/ledger.json`, 비공개 `BROWSER_SETUP.md`, `.local/state/connection.json`을 확인한다. 인증정보를 출력하거나 복사하지 않는다.
3. [복구 스킬](../tistory-engagement-recovery/SKILL.md)에 따라 전용 프로필·확장 연결·로그인 계정·기존 작업기 종료 여부를 먼저 확인한다.
4. 열린 요청은 원래 run ID와 목표를 유지한다. 새 요청만 `run-start`로 시작한다. 구형 열린 회차는 기록을 고쳐 통과시키지 말고 실제 상태를 보고한다.
5. [CLI 계약](references/ledger-cli.md)을 읽고 `session-start`로 실제 실행 문맥의 소유권을 얻는다. 다른 작업기가 활성 상태면 조작하지 않는다.

## 목표와 후보

- 기본 확산3종 순서는 **댓글 → 구독 → 공감(좋아요)** 이다. 한 글을 끝낸 뒤 다음 글로 이동한다.
- **한 바퀴 = 같은 글에서 댓글·신규 구독·공감이 모두 새로 confirmed인 경우 한 건**이다. 인기글+피드 두 글을 한 바퀴로 계산하지 않는다.
- 미구독 인기글 N바퀴는 서로 다른 미구독 블로그 N곳의 실제 인기글을 대상으로 한다. `loops=N`, 세 행동 목표도 N, `unsubscribed_only=true`, `source=popular`를 저장한다.
- 출처는 실제 인기글 목록·로그인 피드에서 확인한다. 검색은 사용자가 요청한 범위에서만 쓴다. 다른 출처나 이미 구독한 블로그로 목표 조건을 바꾸지 않는다.
- 오늘 미방문 글을 고르고 열기 **직전** `visit`으로 기록한다. 기존 별칭·예약·댓글·구독·공감도 대조한다.
- 같은 run이 방문을 기록한 뒤 읽기만 실패했고 행동 예약이 전혀 없다면 새 작업기에서 그 미완료 읽기를 재개할 수 있다. 다른 회차의 방문 기록을 지우거나 바꾸지 않는다.
- 처음 구독 상태, 전체 본문을 읽었는지, 이전 댓글 더보기를 포함한 내 댓글 유무, 공감 활성 여부를 화면에서 확인하고 `article-observe`로 동결한다.
- 공식 canonical 링크·실제 리디렉션 등으로 확인한 별칭만 기록한다. 슬러그/숫자 URL이나 사용자 도메인을 추측해 추가하지 않는다.
- 같은 글의 기존 내 댓글, 이미 켜진 공감, 이미 구독한 계정은 중복하지 않는다. 새 3종 바퀴에 부적합하면 이유를 기록하고 다음 적합 후보를 찾는다. 같은 블로그의 다른 글 댓글만으로 새 글을 제외하지 않는다.
- 접근 실패·후보 제외는 `visit-note`로 남긴다. 방문만으로 확산을 했다고 보고하지 않는다.

## 댓글

[댓글 작성 규칙](references/comments.md)을 읽는다.

- 본문을 읽고 느낀 소감을 친근하고 정겹고 자연스러운 MZ 말투의 짧은 한 문장으로 쓴다. 기본 길이는 8–120자다.
- **처음 방문할 때 미구독이면** 소감 뒤에 정확히 `자주 교류해요~`를 한 번 추가한다. 별표나 따옴표는 넣지 않는다.
- 처음부터 구독 중이면 소감 한 문장만 쓴다. 구독 후에도 처음 관찰값을 바꾸지 않는다.
- 복붙·홍보·맞구독/상호구독 요청·겪지 않은 경험은 제외한다. 계정마다 똑같은 소감을 반복하지 않는다.

## 글마다 실행

1. 댓글 요청을 `reserve`하고 성공한 예약에 한해서 입력·등록을 한 번 실행한다. 내 계정 작성자와 댓글 전문을 실제 목록에서 확인하고 `finish`한다.
2. 댓글이 confirmed일 때 구독을 예약하고 한 번 실행한다. `구독하기 → 구독중` 전환을 확인해 기록한다.
3. 구독 confirmed 후 공감을 예약하고 한 번 실행한다. 비활성→활성 하트와 화면의 변화를 확인해 기록한다.
4. 요청에서 명시적으로 제외된 행동(목표 0)과 기존 완료 행동은 생략하고 이유를 남긴다. 이미 켜진 반응은 토글하지 않는다.
5. 결과가 불확실하면 `uncertain`으로 기록한다. 로딩 중에는 읽기만 갱신하고, 같은 등록/구독/공감을 다시 누르지 않는다. 앞 단계가 미확인이면 해당 글의 다음 단계를 실행하지 않는다.
6. 같은 작업 연속 실패는 복구 스킬로 처리한다. 3회 규칙은 외부 전송을 세 번 반복하라는 뜻이 아니다.

## 끝내기

- 원래 목표를 충족하면 `run-finish`한다. 목표 미달을 completed로 쓰지 않는다. 후보를 더 찾을 수 있으면 같은 run을 계속한다.
- 작업기 인계는 run을 닫지 않고 소유권만 넘긴다. 사용자의 중단 요청, 실제 차단, 후보 소진 등 최종 종료는 정확한 종료 사유로 닫는다.
- **완료·중단·인계마다** [보고 스킬](../tistory-engagement-report/SKILL.md)을 적용한다. `run-finish`는 요약을 자동 저장한다. 열린 run은 `report`로 요약을 저장한다.
- 기존 원장과 영수증을 보존한다. 일일 각 100회, STOP, 중복 예약과 미확인 재전송 금지를 유지한다.
