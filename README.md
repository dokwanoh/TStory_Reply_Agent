# TStory Reply Agent

티스토리 홈 인기글과 로그인 피드의 글을 읽고, 사용자 요청에 따라 댓글 초안 또는 승인된 댓글 게시·공감·구독을 수행하는 프로젝트입니다.

## 현재 상태

- 확산봇 전용 Chrome 프로필 생성 및 기존 게시봇 프로필과 저장 경로 분리 완료
- 기존 티스토리 계정 로그인 및 홈 인기글·이웃 피드 접근 확인 완료
- 공식 ChatGPT 확장을 통한 전용 프로필 연결과 피드 읽기 검증 완료
- 행동별 예약·중복 방지·일일 한도·결과 기록 CLI 구현
- 과거 게시·공감·구독 실행 기록은 로컬 ledger에 보관하며 새 회차의 성과로 합산하지 않음
- 2026-09-27 사용자 재승인에 따라 프로젝트의 초안 전용 제한을 해제하고 실행 권한을 `AGENTS.md`와 `HANDOFF.md`에 기록
- CLI는 브라우저를 직접 조작하지 않으며, 소규모 수동 목표의 회차 종료 기록은 현재 고정 10건 조건과 불일치함. 상세 제약은 `RUNBOOK.md` 참고

## 실행

Codex에 **“RUNBOOK.md에 따라 한 바퀴 실행해줘”** 또는 **“이 댓글을 게시해줘”**라고 요청합니다. 초안만 원하면 **“댓글 초안을 제안해줘”**라고 요청합니다. [실행 절차](RUNBOOK.md)는 전용 연결·기존 활동·기록 조건을 확인한 뒤 요청한 범위의 작업과 실제 결과를 보고합니다.

```sh
uv sync --locked
uv run python -m reply_agent --help
uv run python -m reply_agent status
```

미방문 글을 우선 확인하고, 댓글에는 게시글의 구체적인 내용을 반영합니다. 승인한 댓글 본문은 임의로 변경하지 않습니다. 모델 제한은 없으며 현재 사용자가 선택한 모델을 사용합니다. 프로젝트 지침은 사용자 승인을 다음 대화에 전달하지만 상위 지침·도구 권한을 변경하거나 모든 모델의 동일한 행동을 보장하지 않습니다. 자동화 30은 별도 재개 요청 없이 활성화하지 않습니다.

2026-09-27 사용자 지시로 특정 모델·최저가 모델 강제 규칙과 실행 전 모델 확인 조건을 모두 폐기했습니다. [`.codex/config.toml`](.codex/config.toml)에도 모델을 고정하지 않습니다. Python 기록 CLI는 LLM을 호출하거나 실행 모델을 직접 인증하지 않습니다. 과거 ledger의 `reserve_unavailable` 기록은 이력 호환을 위해 보존합니다.

[기존 구현의 검증 기록](VERIFICATION.md)을 확인하세요. 승인·절차 문서 변경만으로 새 실행이 검증됐다고 주장하지 않습니다.

## 브라우저 분리

기존 게시봇과 같은 티스토리 계정을 사용하면서 별도의 Chrome 프로필과 전용 브라우저 연결을 사용합니다. 프로필을 식별한 뒤 그 안의 탭만 직접 조작하며, 일반 Chrome 앱이나 전역 키보드·마우스 조작으로 대체하지 않습니다.

프로필 분리는 브라우저 상태를 나누는 설정입니다. 동일 계정의 서버 데이터는 공유되며, 이것만으로 두 봇의 동시 실행 안전성을 보장하지 않습니다.

실제 프로필 경로와 연결 식별자는 로컬 `BROWSER_SETUP.md`에 보관하며 Git에 포함하지 않습니다. 새 환경에서는 프로필 생성, 정상 로그인, 전용 연결 확인이 필요합니다.

## 변경 이력

검증한 변경은 의미 있는 단위로 커밋하고 이 저장소에 푸시합니다. 작업 종료 시 로컬 HEAD와 원격 브랜치의 일치를 확인합니다. 인증 정보, 브라우저 프로필 및 개인 실행 기록은 제외합니다.

작업 경계와 동기화 규칙은 [AGENTS.md](AGENTS.md)에 기록합니다.
