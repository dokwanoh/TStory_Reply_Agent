# TStory Reply Agent

티스토리 홈 인기글과 피드의 이웃 글을 대상으로 댓글·공감·구독을 수행하는 봇 프로젝트입니다.

## 현재 상태

- 확산봇 전용 Chrome 프로필 생성 및 기존 게시봇 프로필과 저장 경로 분리 완료
- 기존 티스토리 계정 로그인 및 홈 인기글·이웃 피드 접근 확인 완료
- 공식 ChatGPT 확장을 통한 전용 프로필 연결과 피드 읽기 검증 완료
- Codex 브라우저 실행 절차 및 행동 예약·중복 방지·일일 한도·중단 기록 CLI 구현
- 실제 댓글 1건, 공감 2건, 신규 구독 1건 적용 및 화면 검증 완료
- 회차 가드(`run-start`/`run-finish`)로 스케줄 슬롯 중복·조기 종료·미기록 회차를 차단
- `reply_agent.runner.execute`가 후보 방문 선기록, 미방문 필터, 작업별 예약·확인, 10건 목표와 typed 종료 사유를 한 회차로 묶음
- 브라우저 조작 자체는 Codex의 전용 Chrome 연결에서 수행하며 CLI가 브라우저에 직접 접속하지는 않음

## 실행

Codex에 **“RUNBOOK.md에 따라 확산봇 한 회 실행”**이라고 요청합니다. [실행 절차](RUNBOOK.md)는 전용 브라우저 관찰과 로컬 CLI를 함께 사용합니다. CLI 자체는 브라우저에 접속하거나 댓글을 생성·게시하지 않습니다.

```sh
uv sync --locked
uv run python -m reply_agent --help
uv run python -m reply_agent status
```

댓글·공감·구독은 각각 하루 100회까지입니다. 방문 후보는 미구독 블로그를 우선하며, 후보가 부족할 때만 이미 구독 중인 블로그의 새 글을 방문합니다. `runner.execute`에는 전용 브라우저 연결을 검증하는 `BrowserAdapter`를 주입해야 하며, 연결이 없으면 실행하지 않습니다. 실행 모델은 사용자가 지정한 최저 비용 모델 `reserve`로 고정하고, 선택할 수 없으면 다른 모델로 대체하지 않습니다. 각 회차는 먼저 `run-start`로 슬롯을 등록하고, 모든 행동 뒤 `run-finish`로 목표 달성 또는 후보 소진·제한·차단 사유를 닫아야 합니다. 열린 회차가 남아 있으면 다음 행동 예약을 막습니다. 댓글 중복은 게시글 단위로 판단하며, 같은 블로그라도 다른 게시글에는 댓글을 작성합니다. `.local/state/STOP` 파일이 있으면 다음 행동 예약을 막습니다. 인증값·상태·댓글 기록은 `.local/`에만 저장합니다.

[검증 결과와 미검증 범위](VERIFICATION.md)를 확인하세요.

## 브라우저 분리

기존 게시봇과 같은 티스토리 계정을 사용하면서 별도의 Chrome 프로필과 전용 브라우저 연결을 사용합니다. 프로필을 식별한 뒤 그 안의 탭만 직접 조작하며, 일반 Chrome 앱이나 전역 키보드·마우스 조작으로 대체하지 않습니다.

프로필 분리는 브라우저 상태를 나누는 설정입니다. 동일 계정의 서버 데이터는 공유되며, 이것만으로 두 봇의 동시 실행 안전성을 보장하지 않습니다.

실제 프로필 경로와 연결 식별자는 로컬 `BROWSER_SETUP.md`에 보관하며 Git에 포함하지 않습니다. 새 환경에서는 프로필 생성, 정상 로그인, 전용 연결 확인이 필요합니다.
